\clearpage\section{Reproducing the report without new experiments}
From the repository root:
\begin{verbatim}
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
make assets
make report
make check
\end{verbatim}
\texttt{make assets} runs \texttt{analysis/coursework.py}. It reads saved outputs and cached
exact/reference values without invoking a solver. Tables go to \texttt{report/coursework/},
CSVs to \texttt{results/coursework/}, and plots to \texttt{figures/coursework/}.
\texttt{make report} requires LaTeX with \texttt{latexmk}, builds this PDF and updates the copy
in \texttt{deliverables/}.

The Python checker uses an independent parser/evaluator. A CW output exceeding $K$ is labelled
fleet-infeasible. Timing records carry no route solution and are excluded from route validation.

\textbf{Code map.} \texttt{instance.cpp} parses data; \texttt{solution.cpp} evaluates routes;
\texttt{savings.cpp} implements CW; \texttt{ga.cpp} and \texttt{split.cpp} implement GA/decoding;
\texttt{tabu.cpp} and \texttt{routes.hpp} implement TS/moves. \texttt{medidrone/checker.py}
is independent of C++. Algorithms follow the cited literature. No existing VRP solver library
produces the reported solutions. Comments saying ``own implementation'' mean project-local
code, to be read alongside the AI disclosure.

\texttt{docs/REPRODUCIBILITY.md} lists optional experiment commands. They are outside the default
build. The earlier research report source is \texttt{report/research.tex}, using the original
\texttt{sections/} and \texttt{tables/}; the simplified report uses \texttt{coursework/} inputs.
